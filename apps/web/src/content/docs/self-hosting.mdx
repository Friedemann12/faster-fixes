---
title: Self-hosting
description: Deploy FasterFixes on your own infrastructure. Host the dashboard, the widget API, and the MCP server without relying on the cloud version.
---

FasterFixes is AGPL-3.0. You can deploy the full stack — dashboard, widget API, and background jobs — on your own infrastructure. This guide covers the minimal setup for a production deployment.

The widget packages (`@fasterfixes/core`, `@fasterfixes/react`) are MIT-licensed and can be embedded in any client project regardless of where you host the backend.

## Requirements

You will need:

- A **Docker host** — Coolify is the recommended default (the repo ships a `docker-compose.yaml` for it). Any Next.js host works too (Vercel, Railway, Fly).
- **Bun 1.3+** if you build outside Docker — the repo uses Bun as package manager and runtime.
- A **PostgreSQL database** — in Coolify, add a Postgres resource and pass its connection string as `DATABASE_URL`.
- **Inngest** for background jobs (screenshot processing, GitHub sync, etc.) — the compose file runs a self-hosted Inngest server; Inngest Cloud works too.
- An **S3-compatible object store** for screenshots — MinIO is the default and is bundled in the compose file. AWS S3, Cloudflare R2, or Backblaze B2 work with the same variables.
- A **Resend** or **Plunk** account for transactional email — required to send sign-up confirmations and password resets.
- (Optional) A **GitHub App** if you want the GitHub integration.

Stripe is not needed for self-hosted installs. The billing code only runs on the hosted cloud version.

## 1. Deploy with Coolify

The repo ships a `docker-compose.yaml` covering MinIO, a self-hosted Inngest server, a one-shot migration job, and the Next.js app. Postgres is deliberately not part of it — use a Coolify Postgres resource.

1. Add a **Postgres** resource in Coolify and copy its internal connection string.
2. Create a new resource → **Docker Compose**, point it at this repository, and select `docker-compose.yaml`.
3. Set the environment variables in Coolify:

```bash
APP_URL="https://your-domain.com"
DOMAIN_NAME="your-domain.com"
DATABASE_URL="postgres://..."   # from the Coolify Postgres resource
BETTER_AUTH_SECRET="<openssl rand -base64 32>"

MINIO_ROOT_USER="<random>"
MINIO_ROOT_PASSWORD="<random>"
MINIO_BUCKET_NAME="fasterfixes"
MINIO_PUBLIC_URL="https://s3.your-domain.com"   # public S3 API URL

INNGEST_EVENT_KEY="<openssl rand -hex 32>"
INNGEST_SIGNING_KEY="<openssl rand -hex 32>"

RESEND_API_KEY="re_..."
```

4. Assign domains in Coolify: `your-domain.com` → `ff-web:3000`, `s3.your-domain.com` → `ff-minio:9000`. Add a console domain for `ff-minio:9001` if you want the MinIO UI.
5. Deploy. `ff-migrate` applies Prisma migrations and `ff-minio-init` creates the bucket before `ff-web` starts.

Migrations run on every deploy, so no separate migration step is needed.

## 2. Alternative: deploy to a Node.js host

Fork or clone [the repository](https://github.com/manucoffin/faster-fixes), then deploy the `apps/web` workspace to your host.

```bash
git clone https://github.com/manucoffin/faster-fixes.git
cd faster-fixes
bun install
```

On Vercel, import the repo and set the root directory to `apps/web`. Vercel auto-detects Next.js and Turborepo.

## 3. Configure environment variables

Copy `apps/web/.env.example` and fill in the values. The minimum set for a self-hosted deployment:

```bash
# Core
DOMAIN_NAME="your-domain.com"
BASE_URL="https://your-domain.com"
DATABASE_URL="postgresql://user:password@host:5432/db?schema=public"

# Auth
BETTER_AUTH_SECRET="<generate with: openssl rand -base64 32>"
BETTER_AUTH_URL="https://your-domain.com"

# Storage (MinIO or any S3-compatible store)
STORAGE_ENDPOINT="http://ff-minio:9000"       # S3 API endpoint reachable from the server
STORAGE_REGION="us-east-1"
STORAGE_BUCKET_NAME="fasterfixes"
STORAGE_ACCESS_KEY_ID="..."
STORAGE_SECRET_ACCESS_KEY="..."
STORAGE_PUBLIC_URL="https://s3.your-domain.com/fasterfixes"            # browser-facing

# Inngest (required in production)
INNGEST_EVENT_KEY="..."
INNGEST_SIGNING_KEY="..."

# Transactional email — required for sign-up confirmations and password resets.
# Use either Resend or Plunk.
RESEND_API_KEY="re_..."
# PLUNK_SECRET_KEY="sk_..."

# Widget API (points clients' widgets at your instance)
FF_API_ORIGIN="https://your-domain.com"

# Self-hosted flag (keep false to skip marketing pages)
NEXT_PUBLIC_IS_CLOUD="false"
```

GitHub App variables are optional. Skip them unless you need the GitHub integration. Leave the Stripe variables unset — billing is cloud-only and self-hosted installs don't run it.

Every URL and key above is read at runtime, so the same image serves any instance — a domain change needs a restart, not a rebuild.

## 4. Provision external services

### PostgreSQL

Any Postgres 14+ works. Create a database and put the connection string in `DATABASE_URL`.

### MinIO

Create a bucket and an access key scoped to it. Set the bucket's anonymous policy to `download` so screenshots are readable by reviewers, or keep it private and serve assets through signed URLs.

Two URLs matter and they are usually different: `STORAGE_ENDPOINT` is what the server calls (inside the Docker network, `http://ff-minio:9000`), while `STORAGE_PUBLIC_URL` is what browsers load. Set MinIO's `MINIO_SERVER_URL` to the public S3 API URL, otherwise presigned URLs point at the internal hostname.

### Inngest

Create an app at [inngest.com](https://www.inngest.com). Copy the event key and signing key. After your first deployment, connect Inngest to your instance at `https://your-domain.com/api/inngest`.

## 5. Run migrations

Skip this if you deployed with Coolify — the `ff-migrate` service handles it. Otherwise, from the repo root:

```bash
bun run --filter @workspace/db migrate:dev
```

This applies all Prisma migrations and generates the client. For subsequent deploys, your host's build step should run `prisma generate`; Prisma migrations are committed to the repo and applied via `migrate:dev` in development and `migrate:deploy` in production (run this as part of your deploy pipeline).

## 6. Verify

After the first deploy:

1. Visit `https://your-domain.com/login` and create the first account (becomes the admin).
2. Create a project, copy the widget API key, and test the widget in any page.
3. Check Inngest's dashboard to confirm events are being received.

Your instance is now ready. Point your clients' widgets at `FF_API_ORIGIN` and connect your AI coding agent via the [MCP server](/docs/mcp/setup).
